▶ Thumbnail automática de vídeo no card da aula Alto
Impacto visual

Cada card de aula deveria mostrar um frame do vídeo como preview. Hoje o card é texto puro — o aluno não consegue identificar visualmente o conteúdo antes de clicar. A diferença entre Coursera e um gerenciador de arquivos é exatamente essa.

Como implementar: Na indexação, rodar ffmpeg -ss 5 -i video.mp4 -frames:v 1 -q:v 2 thumb.jpg uma vez por arquivo. Salvar o path no SQLite. O card exibe <img src="/api/thumb?id=..."> com lazy loading. Geração em background, não bloqueia a UI.
▶ Atalho de teclado global para retomar exatamente onde parou Alto
Fricção eliminada

O usuário abre o browser, digita localhost:3000 e ainda precisa clicar no botão "Continuar". Esse clique é fricção. Uma URL permanente tipo localhost:3000/now que redireciona direto pro vídeo no segundo exato elimina qualquer decisão.

Como implementar: Rota /now que lê o registro mais recente do SQLite (última aula + timestamp). Redireciona para /track/[id]/[aula]?t=SEGUNDOS. O player inicia autoplay no segundo salvo. Adicionar esse link como atalho de browser ou script de inicialização.
▶ Picture-in-picture nativo + notas simultâneas Alto
Produtividade

A API Picture-in-Picture do browser permite que o vídeo flutue sobre qualquer janela. O aluno poderia assistir a aula enquanto escreve código ou anotações no VS Code — sem sair do Studium e sem gerenciar duas janelas manualmente.

Como implementar: Botão PiP no player: videoEl.requestPictureInPicture(). Quando PiP ativa, mostrar na lateral direita um textarea de notas vinculado à aula atual (salva em SQLite com timestamp do vídeo). Ao fechar PiP, nota fica ancorada no segundo exato.
▶ Marcadores de tempo no vídeo (bookmarks) Médio
Revisão de conteúdo

Durante a aula o aluno pressiona "M" e cria um marcador no segundo atual com uma nota rápida ("não entendi isso", "revisar amanhã"). A barra de progresso exibe os marcadores como pontos. Ao retornar, clicar no ponto salta direto para aquele momento.

Como implementar: Tabela SQLite: bookmarks(lesson_id, timestamp_s, note, created_at). Atalho "M" no player abre um input inline de 2 segundos. Barra de progresso renderiza <div style="left: X%"> para cada marcador. Clique no marcador faz video.currentTime = timestamp.
▶ Velocidade de reprodução persistida por disciplina Médio
Conforto de uso

Você assiste Rocketseat em 1.5x mas Uninter em 1.0x. Hoje toda vez que abre um vídeo precisa ajustar a velocidade. A preferência deveria ser salva por track — ao abrir qualquer aula da Rocketseat, já iniciar em 1.5x automaticamente.

Como implementar: Coluna playback_speed na tabela de tracks no SQLite. Ao mudar velocidade no player, salvar via PATCH /api/tracks/[id]/preferences. Player lê a preferência no mount e aplica video.playbackRate.
▶ Worker thread dedicado para indexação assíncrona Alto
Performance

A indexação de PDFs e vídeos (thumbnails, FTS5) hoje bloqueia o thread principal do Node.js. Com 1134 aulas da Rocketseat, a primeira abertura do app vai congelar por minutos. Mover para um Worker Thread isola completamente o processamento pesado.

Como implementar: src/lib/indexer.worker.ts usando a API worker_threads nativa do Node. O app principal dispara o worker no startup com new Worker('./indexer.worker'). Worker envia eventos de progresso via parentPort.postMessage. UI mostra barra de indexação discreta no header.
▶ Cache de metadados com invalidação inteligente Alto
Velocidade de abertura

Toda vez que o aluno abre uma disciplina, o motor lê o sistema de arquivos novamente. Com 200+ arquivos por curso, isso cria latência visível. O SQLite já está disponível — usá-lo como cache de metadados com hash de mtime elimina re-scans desnecessários.

Como implementar: Ao escanear, salvar file_path, mtime, size, metadata_json no SQLite. Na próxima abertura, comparar o mtime atual com o cached. Se igual, usar cache. Se diferente, re-indexar apenas aquele arquivo. Tempo de abertura cai de ~800ms para ~20ms.
▶ Watcher de sistema de arquivos para hot-reload do conteúdo Médio
Conforto de uso

Quando o Kauã baixa um novo vídeo ou PDF na pasta /library, precisa reiniciar o servidor para o app reconhecer. Com fs.watch ou chokidar, o backend detecta automaticamente arquivos novos e atualiza o índice em tempo real sem restart.

Como implementar: chokidar.watch('/library') no startup do servidor. Eventos add e unlink disparam re-indexação incremental. O frontend recebe notificação via Server-Sent Events (/api/sse) e atualiza o feed sem reload de página.
▶ Migrations versionadas para o SQLite Médio
Durabilidade

Hoje o schema do SQLite é criado no startup sem versão. Quando uma feature nova adicionar uma coluna, o banco existente com progresso real do Kauã vai quebrar. Migrations versionadas garantem que o banco evolua sem perder dados.

Como implementar: Pasta src/lib/migrations/ com arquivos 001_initial.sql, 002_add_bookmarks.sql, etc. No startup: PRAGMA user_version para saber a versão atual, rodar só as migrations pendentes. Sem dependência externa — pure better-sqlite3.
▶ Script de backup automático diário para repo privado Baixo
Segurança dos dados

O progresso, bookmarks e notas ficam só no SQLite local. Se o HD morrer antes do backup manual, tudo se perde. Um cronjob que roda o backup-config.sh diariamente, incluindo o SQLite serializado, garante que o histórico de estudo nunca suma.

Como implementar: scripts/backup-daily.sh usando sqlite3 studium.db .dump > backup_$(date).sql. Cronjob via crontab: 0 2 * * * /path/backup-daily.sh. Manter últimos 7 backups, deletar os mais antigos automaticamente. Push para o repo privado na branch backups/.
▶ Geração automática de resumo da aula ao finalizar Alto
Retenção de conhecimento

Quando o aluno marca uma aula como concluída, o sistema roda o PDF vinculado pelo nomic-embed + qwen para gerar automaticamente 3–5 bullet points de resumo. Eles aparecem na tela de vitória (confetti) como "o que você aprendeu hoje". Reforço de memória imediato.

Como implementar: Na API POST /api/lessons/[id]/complete, disparar em background: extrair texto do PDF, enviar para qwen2.5 com prompt de resumo em bullets. Salvar resultado em lessons.summary_md. Mostrar na tela de vitória e disponibilizar no Ghost Card após deleção do vídeo.
▶ Perguntas socrátisas automáticas pré-aula (modo revisão) Alto
Aprendizado ativo

Antes de abrir uma aula nova, o sistema mostra 2–3 perguntas sobre a aula anterior ("O que é hoisting em JavaScript?"). O aluno responde em texto livre, a IA avalia e só então libera a próxima aula. Isso ativa a memória antes de adicionar nova informação — técnica de retrieval practice comprovada.

Como implementar: Na aula N, ao concluir, gerar perguntas do resumo e salvar em SQLite. Na abertura da aula N+1, exibir o modal socrático antes do player. Resposta do aluno vai pro Ollama com o resumo como contexto. Score > 60% libera. Score < 60% sugere revisar, mas deixa prosseguir.
▶ Busca semântica unificada (PDF + vídeo + notas) Alto
Utilidade diária

Ctrl+K hoje busca só por nome de arquivo. Deveria buscar por conteúdo: "ponteiros em C" encontra o PDF da Uninter de SO, a aula 142 da Rocketseat e a nota que você criou semana passada. Uma busca única varre todo o conhecimento acumulado.

Como implementar: Pipeline: PDF → pdfplumber extrai texto → chunks de 512 tokens → nomic-embed-text gera embeddings → sqlite-vec ou FAISS salva vetores. Busca: query → embedding → cosine similarity top-5. Combinar com FTS5 (keyword) por rank fusion. Resultado mostra fonte, trecho e botão de abrir.
▶ Detecção automática de dúvida por pausa no vídeo Médio
Suporte contextual

Se o aluno pausar o vídeo mais de 3 vezes em menos de 2 minutos, o sistema detecta como "sinal de confusão". Aparece um toast discreto: "Está com dúvida nesse trecho? Ctrl+K para perguntar ao chat." Não é intrusivo, mas aparece exatamente quando precisaria.

Como implementar: Contador de pauses no estado do player. Se pauseCount >= 3 em 120s E timeRange < 120s, disparar toast. Toast desaparece sozinho em 8s. Ao clicar, abre Ctrl+K com contexto pré-preenchido: "Estou na aula X, minuto Y, com dúvida sobre...".
▶ Modo "Sprint 25min" com bloqueio de navegação Alto
Foco real

Um botão "Iniciar Sprint" esconde o dashboard, desativa Ctrl+K e bloqueia qualquer navegação fora do player pelo tempo configurado (25min por padrão). O único botão visível é "Pausar Emergência" que exige confirmar 2 vezes. Quando o timer zera, aparece a tela de vitória com estatísticas do sprint.

Como implementar: Context global SprintContext com estado isActive. Durante sprint ativo, os componentes de navegação retornam null. O router intercepta mudanças de rota com useRouter().beforePopState e redireciona de volta. Timer no header com contagem regressiva visível.
▶ Streak visual diário com calendário de calor (heatmap) Alto
Motivação contínua

Um GitHub-style heatmap no dashboard mostrando os dias que você estudou nos últimos 3 meses. Cada célula é colorida pela quantidade de minutos de estudo. Quebrar um streak de 7 dias causa mais dor que qualquer notificação — isso é dopamina real sustentada.

Como implementar: Tabela SQLite study_sessions(date, minutes, lessons_completed). Atualizada ao completar aulas e ao pausar vídeos. Dashboard renderiza um grid 7×13 de divs coloridos por intensidade usando as CSS vars de sucesso/warning. Tooltip mostra o resumo do dia ao hover.
▶ Meta diária configurável com progresso em tempo real Médio
Direção clara

No topo do dashboard: "Meta de hoje: 3 aulas | 1 concluída". A barra de progresso avança em tempo real conforme o aluno assiste. Quando bate a meta, uma animação de vitória menor (sem confetti excessivo) marca o checkpoint. Fornece ao cérebro TDAH uma linha de chegada clara e próxima.

Como implementar: Config por track em data/config.json: "daily_goal": 3. Componente <DailyGoal> lê o progresso do dia no SQLite e atualiza via SWR com revalidate a cada 30s. Ao atingir meta, escreve goals_met(date, track_id) e dispara a animação.
▶ Check-in socrático pré-estudo (Protocolo MIT) Médio
Ancoragem cognitiva

A Fase 8 do Master Plan descreve isso mas sem implementação. Ao abrir o app, antes de mostrar o dashboard, exibir 3 perguntas rápidas: "Humor atual (1–5)", "Distração principal hoje", "Uma coisa que vai focar". Dura 20 segundos. Serve como âncora cognitiva que desativa o modo piloto automático.

Como implementar: Modal de check-in no primeiro acesso do dia (comparar last_checkin_date no SQLite com today). 3 inputs simples. Respostas salvas em daily_checkins. Após 30 dias, o histórico alimenta o Ollama para detectar padrões ("você estuda pior às segundas após humor < 3").
▶ Numeração unificada de fases entre todos os documentos Alto
Clareza para agentes IA

AGENTES.md, Master Plan e Status Report usam numerações incompatíveis. Um agente novo lendo os três documentos não sabe em qual fase está o projeto. Isso desperdiça tokens e cria risco de regressão (re-implementar algo que já existe). A numeração deve ser idêntica em todos os documentos.

Como implementar: Definir fases 1–10 no AGENTES.md como fonte de verdade. Cada fase tem: número, nome, status (Concluído / Em progresso / Pendente / Bloqueado) e uma linha de descrição. Status Report e Master Plan referenciam os números, não redefinem. CHANGELOG usa os mesmos números nos commits.
▶ Health check endpoint para monitorar serviços locais Médio
Diagnóstico rápido

Quando algo quebra, o aluno não sabe se é o Next.js, o Ollama, o SQLite ou o Kiwix. Um endpoint /api/health retorna o status de cada serviço em JSON. Um indicador no corner do dashboard mostra verde/amarelo/vermelho. Um clique revela qual serviço caiu e o erro exato.

Como implementar: GET /api/health testa: SQLite (query simples), Ollama (GET :11434/api/tags com timeout 2s), Kiwix (GET :8080 com timeout 2s), espaço em disco via df. Responde em <500ms. Badge no layout global: verde se tudo ok, vermelho se qualquer serviço falhou.
▶ Testes E2E para os fluxos críticos com Playwright Médio
Regressão zero

O projeto não tem nenhum teste. Quando uma feature nova quebra o seek de vídeo ou o progresso, só se descobre manualmente. 3 testes E2E cobrem os fluxos críticos: abrir vídeo → seek → progresso salvo → continuar de onde parou. Custo baixo, prevenção de regressões alta.

Como implementar: Playwright com um arquivo de fixtures que simula a pasta /library com 2 vídeos de teste (10s cada). Teste 1: play + seek + fechar + reabrir verifica timestamp. Teste 2: marcar aula concluída → próxima aparece. Teste 3: busca Ctrl+K retorna resultado. Rodar com npm run test:e2e.
▶ Logs estruturados com níveis e rotação automática Baixo
Depuração eficiente

Hoje os erros aparecem só no terminal do Next.js e somem quando o servidor reinicia. Um logger estruturado (nível + timestamp + contexto) salvo em arquivo permite investigar bugs que ocorreram durante uma sessão de estudo sem reproduzir manualmente.

Como implementar: pino (zero-dependency, extremamente rápido). src/lib/logger.ts exporta uma instância singleton. Logs em data/logs/app-YYYY-MM-DD.jsonl. Rotação: manter últimos 7 dias. Nível configurável via env: LOG_LEVEL=debug npm run dev. Erros de vídeo com requestId para rastrear seeks específicos.
