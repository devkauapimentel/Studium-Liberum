I am very sad that designated initializers are restricted to being only in declared order. Omitting some fields and using the others in don't-care ordering was the entire reason this feature existed and was useful in C99, making this a complete misfeature that is utterly useless to add to the language in the present form. 124.157.79.144 15:27, 2 November 2020 (PST)

Designated initializes (as they are in C++20) can nonetheless be useful (at least) to:
  • emulate named actual parameters,
  • emulate function's default parameters skipping: 
#include <iostream>
 
struct S { int i{}; double d{}; char c{'a'}; };
 
void foo(S s) {
    std::cout << "S { i = " << s.i << "; d = " << s.d << "; c = '" << s.c << "'; };\n";
}
 
int main() {
    foo({});                         // OK: S { i = 0; d = 0; c = 'a'; };
    foo({.i = 2});                   // OK: S { i = 2; d = 0; c = 'a'; };
    foo({.d = 3,});                  // OK: S { i = 0; d = 3; c = 'a'; };
    foo({.c = 'A',});                // OK: S { i = 0; d = 0; c = 'A'; };
    foo({.i = 3, .c = 'B'});         // OK: S { i = 3; d = 0; c = 'B'; };
    foo({.i = 4, .d = 5});           // OK: S { i = 4; d = 5; c = 'a'; };
    foo({.d = 6, .c = 'C'});         // OK: S { i = 0; d = 6; c = 'C'; };
    foo({.i = 7, .d = 6, .c = 'D'}); // OK: S { i = 7; d = 6; c = 'D'; };
//  foo({.d = 8, .i = 9});           // Error: designator order mismatch.
}

[edit] missing-field-initializers warning when fields are not initialized in aggregate initialization

I added in a previous version a note, below these code lines:

A a{.x = 1, .z = 2}; // ok, b.y initialized to 0

A b{.y = 2}; // ok, b.x and b.z are initialized to 0

Saying:

// note: some compilers may issue a "missing-field-initializers" warning for above lines

// for not initializing all members, even though members are initialized by default to {}

(See for example: https://godbolt.org/z/9jjoP4YP5)

This note was added following a discussion in another forum where it was not clear to some of the audience that the warning doesn't say that the fields are not initialized! (i.e. a few people were confused by the warning and argued, wrongly, that the fields are uninitialized - because of the warning). Thus, I believe that leaving this note on the page may be useful to some of the readers, to avoid this confusion.
