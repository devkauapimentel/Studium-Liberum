Inconsistências críticas nos documentos
⚠

Status Report afirma "Fase 5 concluída" — mas IA não existe

O documento diz "Fases 1 a 5 Concluídas", mas o AGENTES.md lista Ollama como "previsto na arquitetura". Nenhum código de RAG, embedding ou chat modal foi entregue. A Fase 5 está a 0%.

⚠

Numeração de fases inconsistente entre documentos

O Master Plan começa na Fase 4. O Status Report fala em "Fases 1–5". O AGENTES.md não usa numeração de fases. Não é possível saber em qual fase real o projeto está sem correlacionar os 3 docs manualmente.

⚠

Modelos Ollama divergentes entre os documentos

Master Plan cita phi4:14b, deepseek-coder-v2:16b, nomic-embed-text. AGENTES.md lista qwen2.5-coder 14b/7b, qwen2.5 14b, qwen3.5. Os modelos planejados e os instalados não batem — a lógica de seleção automática vai falhar.

⚠

Fase 4 "Motor V3" não aparece no AGENTES.md como pendente

O mapeamento cruzado da Rocketseat (tag #F0001 → messages.html → sumario.md) e o Binder de PDFs da Uninter estão descritos apenas no Master Plan, mas o AGENTES.md e o CHANGELOG não os listam como tarefas abertas.

Gaps técnicos por camada
Crítico

Seek de vídeo ainda usa fs.promises.read (chunking manual)

A Fase 6 define a correção (Web Streams + fs.createReadStream + AbortController global), mas o código atual ainda usa o ReadableStream de 256KB citado no AGENTES.md. A implementação correta ainda não foi feita.

Crítico

SQLite FTS5 está "preparado" mas não indexando nada

O stack menciona SQLite FTS5 para buscas offline, mas nenhuma pipeline de indexação (PDFs → chunks → FTS5 ou embeddings) foi implementada. A busca unificada não existe.

Alto

Parser Rocketseat usa sumario.txt — V3 requer DOM parse do messages.html

A lógica atual ordena por sumario_rocketseat.txt. O Motor V3 exige um parser HTML adicional para extrair títulos reais via tag #FXXX no messages.html do Telegram. São dois sistemas distintos que precisam coexistir.

Alto

Progresso salvo em localStorage E progress.json — fonte de verdade dupla

AGENTES.md menciona que o progresso da 42-prep passará do localStorage para SQLite, mas o sistema atual usa ambos. Há risco real de dessincronização entre as fontes.

Médio

Auto-shutdown do Ollama (keep_alive: 0) sem cronjob implementado

O Master Plan descreve o mecanismo com precisão, mas nenhum serviço de background existe ainda. Sem isso, LLMs travam a VRAM durante sessões longas de vídeo.

Médio

docs/ ainda vazio — IA não tem contexto para RAG sobre o software

O AGENTES.md planeja 7 arquivos em docs/ que alimentam tanto humanos quanto o Ollama. Nenhum foi criado. Quando o chat IA for implementado, ele não saberá responder perguntas sobre o próprio Studium.

Roadmap priorizado (próximos sprints)
1
Corrigir seek de vídeo — Fase 6 Bloqueante
Substituir chunking manual por fs.createReadStream + AbortController. Sem isso, o produto é inutilizável para aulas longas.
2
Unificar fonte de verdade do progresso Dívida técnica
Migrar localStorage + progress.json para SQLite como fonte única. Implementar hook useProgress() que lê/escreve apenas no banco.
3
Completar Motor Semântico V3 — Fase 4 Alta prioridade
Implementar parser DOM do messages.html para extração de títulos reais da Rocketseat. Implementar Binder de PDFs para Uninter.
4
Pipeline de indexação SQLite FTS5 Desbloqueador de IA
Criar indexador que varre /library, extrai texto de PDFs e alimenta FTS5. Isso desbloqueia busca offline E prepara base para RAG.
5
Sincronizar modelos Ollama entre documentos Consistência
Atualizar Master Plan para refletir os modelos reais (qwen2.5-coder, etc.). Ou definir quais instalar e atualizar AGENTES.md. Documentos não podem divergir.
